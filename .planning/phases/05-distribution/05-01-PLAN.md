**1. `/healthz` returning 200 no longer means the plant is live.**
The WINDOWS-15 fix (quick task 260823-tkx) moved the simulator's control server
to start BEFORE the warm-start burst, because compose gates the worker on the
simulator's healthcheck and the two would otherwise deadlock. Consequence: the
simulator reports healthy, and `docker compose up -d --wait` returns, while the
warm-start day is still unpublished.
`/healthz` now also returns `warmStartComplete` and `ingestorReady` for exactly
this reason. **Both `smoke.sh` and `demo-scenario.ts`: `pnpm demo` -- **`docker compose down -v` first**, then up with env override `SIM_SPEED=120` (seed stays the plant.config default 42; warm-start is unconditional per 01-03 -- there is NO separate DEMO flag). The `down -v` is not optional: after the WINDOWS-14 fix a restart RESUMES the stored clock, so without a clean volume each take starts from a different plant state and the demo stops being deterministic. Wait for `/healthz` to report **`warmStartComplete: true`** (delta 1 -- HTTP 200 now arrives before the burst), THEN run the scripted timeline via the control API: t+30s inject L2 breakdown (240 sim-min -- long enough to flip an order late), print the cue card ('Now open Orders -- watch ORD-xxx go AT_RISK'). Fresh boot lands at go-live 06:55 and S1 opens at 07:00, so at 120x the inject at t+30s falls at sim ~07:55, safely inside a shift -- but a session that keeps running crosses the dead window every 12 real minutes (delta 2), so **each take must be a fresh `pnpm demo`**, not a resumed stack. If the script ever sees a 404 from inject-breakdown, it must say so in plain language ('the simulated plant is between shifts -- re-run `pnpm demo`') rather than dying obscurely.
`warmStartComplete: true`, not merely for HTTP 200.**

**2. The plant is completely idle for a third of every sim-day.**
Shifts are S1 07:00-15:00 and S2 15:00-23:00, so sim 23:00-07:00 produces
NOTHING. Measured 2026-08-23: `machine_event` has **0 rows of any kind** in
23:30-06:30, against 11,812 COUNTS in a single daytime hour. During that window
`POST /control/inject-breakdown` 404s ("no injectable machine found" -- nothing
is in EXECUTE) and every andon tile reads BREAK. Tracked as WINDOWS 16.

**3. A restart no longer rewinds the clock -- only `down -v` does.**
The WINDOWS-14 fix (quick task 260823-uib) made the simulator RESUME from the
newest stored event on restart instead of warm-starting over it. That killed
the old desync bug, but it also means `docker compose restart` keeps the clock
wherever it was, including inside the dead window above. **`down -v` is now the
only way back to go-live** -- which `pnpm demo` needs anyway, since a scripted
demo cannot be deterministic if it starts from whatever state the last take
left behind.

**4. `README.md` already exists** (quick task 260823-vtw). Task 2 is now an
extend-and-complete, not a from-scratch write. See that task for the delta.
