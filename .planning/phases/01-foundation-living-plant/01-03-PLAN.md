<task type="auto">
  <name>Task 2: Machine state machine (sim-time domain)</name>
  <files>apps/simulator/src/machine.ts, apps/simulator/src/plant.ts</files>
  <action>
    Hand-rolled discriminated-union state machine (STACK.md: no XState). THE CORE RULE: the machine's entire life is computed in SIM-TIME; the real-time loop only asks "advance to simNow". Internal model per machine:
    ```ts
    type Pending = { at: number /*simMs*/, fire: () => void };  // next scheduled transition
    interface MachineRuntime { state: MachineState; stateSince: number; seq: number;
      goodTotal: number; rejectTotal: number; lastRecoveryAt: number | null;
      nextFailureAt: number; nextChangeoverAt: number; nextMicrostopAt: number; cycleAccumMs: number; }
    ```
    Transition logic (advance(machine, toSimMs) processes ALL due internal events in sim-time order, emitting contract events; each emitted event carries `simTime` = the sim instant it logically happened, NOT simNow-at-tick — this is what makes speed-invariance hold):
    - Shift calendar drives BREAK: entering a break/no-shift window → STATE_CHANGE BREAK (reasonCode null); window end → back to EXECUTE (or DOWN if a repair is still pending — repairs pause during breaks? NO: keep simple & defensible: repairs continue through breaks; changeover schedule defers to next EXECUTE).
    - Failures: at machine start and after each repair, draw `nextFailureAt = now + exponential(mtbfMin)` counting only EXECUTE time (accumulate execute-ms; compare against drawn TTF in execute-time domain). On fire: STATE_CHANGE DOWN with reason drawn uniformly from {BRK-MECH (50%), BRK-ELEC (30%), BRK-SENSOR (20%)}; repair duration = `mttrMeanMin * triangular(0.5, 1.0, 1.8)`; on completion: STATE_CHANGE EXECUTE, set `lastRecoveryAt`.
    - Changeovers: every `changeoverEveryMin` of EXECUTE time: STATE_CHANGE CHANGEOVER reason CO-PRODUCT (rotate product to next in config → subsequent COUNTS carry the new productId+ICT); duration = `changeoverDurMin * triangular(0.8, 1.0, 1.4)`. The TARGET (`changeoverTargetMin`) is NOT sent in telemetry — it is machine master data the engine reads from config/db (02-01 seeds it); the simulator just runs realistic durations that sometimes exceed target (typical/problem presets have dur>target on purpose → engine's overage split has real material).
    - Production (while EXECUTE): effective cycle = `ICT * slowCycleFactor * uniform(0.97, 1.06)`. Accumulate cycles; batch-emit COUNTS every 5 sim-seconds: goodDelta/rejectDelta per accumulated cycles. Reject draw per unit: p = `startupRejectRate` if within `startupWindowMin` after lastRecoveryAt/changeover end (rejectReason RJ-STARTUP) else `rejectRate` (reason RJ-DIM 70% / RJ-VISUAL 30%).
    - Micro-stops (while EXECUTE): schedule via exponential(3600/microstopsPerHour sec of execute time); when fired: production pauses for `microstopMeanSec * triangular(0.4,1.0,2.2)` sim-sec, then emit ALARM MICROSTOP {reasonCode: SS-MISFEED 40%/SS-MATERIAL 40%/SS-SENSOR 20%, durationSec}. NO state change (machine stays EXECUTE) — this is the verified small-stops-are-Performance semantics.
    `plant.ts`: builds all machines from plant.config.json, exposes `advanceAll(toSimMs)` and injected-event API.
  </action>
