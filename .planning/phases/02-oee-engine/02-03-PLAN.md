  <name>Task 1: OEE SQL views</name>
  <files>packages/db/src/views.sql, packages/db/prisma/migrations/*</files>
  <action>
    A `views.sql` applied via migration (CREATE OR REPLACE). Definitions — formulas verbatim from §2:
    - Helper `v_shift_windows`: shift instances per sim-day (generate_series over days present in machine_event × Shift rows) with break windows; effective end = LEAST(shift_end, sim_now()).
    - `v_machine_shift_oee` per (machine, shiftDate, shiftId), all in seconds, every interval clamped to the shift window AND to sim_now() (open intervals: end = LEAST(sim_now(), shift_end) — ENG-06 open-interval clamping):
      ```
      ppt        = (effective_end - shift_start) - elapsed_break_overlap        -- SIM-07 semantics
      down       = Σ clamped DOWN interval seconds
      changeover = Σ clamped CHANGEOVER interval seconds
      run_time   = ppt - down - changeover
      total_cnt  = Σ good_delta + reject_delta   (COUNTS in window)
      good_cnt   = Σ good_delta
      ict_time   = Σ (ideal_cycle_time_sec * (good_delta + reject_delta))       -- per-event ICT
      availability = run_time  / NULLIF(ppt, 0)
      performance  = ict_time  / NULLIF(run_time, 0)
      quality      = good_cnt::float / NULLIF(total_cnt, 0)
      oee          = availability * performance * quality                        -- NULL propagates
      ict_misconfigured = (performance > 1.0)                                    -- ENG-05: FLAG, never clamp
      -- waterfall time buckets (min): a_loss = ppt - run_time; p_loss = GREATEST(0, run_time - ict_time); q_loss = ict_time * (1 - quality)
      ```
    - `v_line_shift_oee`: aggregate machines per line: A = Σrun/ΣPPT, P = Σict_time/Σrun, Q = Σgood/Σtotal, oee = A*P*Q (aggregate-of-sums, NOT average-of-ratios — document why in a SQL comment).
    - `v_loss_pareto`: from loss_event: (lineId, shiftDate, shiftId, category, reasonCode, Σ lostTimeSec, Σ lostUnits) — Phase 4's Pareto reads this.
    - BREAK intervals never appear in down/changeover sums (they're excluded from PPT already — subtracting twice is the classic PPT-vs-calendar bug in PITFALLS; add an SQL comment + test).
    - Defense-in-depth: when summing DOWN/CHANGEOVER seconds, ALSO subtract any overlap with break windows (normally zero because the simulator emits BREAK state changes at break boundaries, but the view must not depend on producer discipline — a DOWN overlapping a break would otherwise be double-subtracted from PPT). Apply the same break-overlap exclusion to run_time math anywhere it is computed (incl. 02-02 rule 4's slow-cycle runTimeSec).
    - Row-absence = N/A: `v_machine_shift_oee` emits NO ROW for a (machine, shift) with zero machine_event rows in the window — never a zero-filled row (a no-events shift must read as N/A, not as A=100%/P=0). The API layer treats missing row as N/A.
  </action>
