<task type="auto">
  <name>Task 1: Drill-down SQL function</name>
  <files>packages/db/src/views.sql, packages/db/prisma/migrations/*</files>
  <action>
    `order_loss_drilldown(order_id)` (SQL function, on-read — data volume is tiny):
    1. Resolve order → productId → line(s) whose machines run that product (machine.currentProductId OR any COUNTS event for that product in the window — use the events; product rotation means multiple lines possible).
    2. Window = `[orderDate, COALESCE(shippedAt, GREATEST(dueDate, sim_now()))]`.
    3. Select loss_event rows on those lines overlapping the window; per row compute `est_lost_units`:
       - AVAILABILITY & PERFORMANCE losses: `lost_time_sec / product.ideal_cycle_time_sec` (units the line would have produced in that lost time);
       - QUALITY losses: `lost_units` directly.
    4. Return ranked by est_lost_units DESC, limit 12: {category, reasonLabel, machineId, lineId, windowStart, windowEnd, lostTimeSec, estLostUnits, injected}.
    5. Also return the order's shortfall context: `short_units = qtyOrdered − allocated_at_due` (0 if shipped on time) and `total_est_lost_units` — the drill-down headline compares these: losses ≥ shortfall makes the story arithmetically coherent.
    - SQL AUTHORING CONTRACT (Phase-02, 02-03): `order_loss_drilldown` goes in `packages/db/src/views.sql`, which is the single hand-maintained source; the migration under `packages/db/prisma/migrations/*` carries a BYTE-IDENTICAL copy of it. Migrations are immutable once applied — always create a NEW migration, never edit an existing one in place (rule stated in views.sql's own header, lines 7-14).
    - SIM-TIME CAST RULE (Phase-02 contract, silent-corruption class): every sim-time column in this schema is `timestamp(3) WITHOUT TIME ZONE` (naive) while `sim_now()` returns `timestamptz`. Step 2's window `COALESCE(shippedAt, GREATEST(dueDate, sim_now()))` MUST be written `GREATEST("dueDate", sim_now() AT TIME ZONE 'UTC')` — bare `sim_now()` silently shifts the whole window under a non-UTC Postgres session, returning plausible-but-wrong losses with no error. Copy the clamp form verbatim from `packages/db/src/views.sql`. The same rule applies to `customer_order.orderDate/dueDate/shippedAt`, which 04-01 creates as naive sim-time columns.
  </action>
  <verify>SQL test on a fixture database: known losses + known short order → function returns them ranked with correct est_lost_units (hand-computed: 45-min breakdown at ICT 60s → 45 est lost units).</verify>
  <done>The bridge query exists and is auditable SQL.</done>
